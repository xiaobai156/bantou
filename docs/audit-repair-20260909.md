# 审查修复说明（2026-09-09）

基线提交：`d35d3a43f8dd0ce4aafb522939e5c668ca8474a9`。

## 改动范围

完整记录的不同半头值进入既有边界冲突裁决；非边界同期记录仍不参与裁决。
表格不删除空格位，不再把跨行的无栏目单元格拼成半头记录；记录和表头保存真实源文档位置。
不支持的复杂嵌套/合并表格不猜测列位，需专属解析器和真实样本验证。

正式写入前精确验证每期只能有一条合法结果。缓存候选存在冲突时不写回缓存，但不把实时成功结果改成失败。
失败文件必须绑定目标期，站名与完整URL必须成对匹配；错误期数、混合身份和理由中的其他网址不会扩大重跑范围。
旧四列失败文件仍可用，但必须有对应期号文件名；显式五列文件可使用自定义路径。
重抓的读写路径一致；历史重抓不能更新正式缓存；已有成功值有冲突时不改写或清除失败记录。

多期汇总复用正式成功格式读取器，统一三位期号，离散期号和连续范围文件名不再碰撞。
单期入口只接受一期；独立验证的多期输入逐期运行。
已存在的整期成功输出默认不覆盖；整期替换必须在CLI显式传入 `--replace-existing`。
自定义站点配置、目标值筛选只可与 `--diagnose` 使用，不得写入正式输出和缓存。

正式判重固定使用10期。退出码：0通过、2未完成、3待人工审核、4重复拒收。
专项名称只改变报告展示，不再隐式免除重复规则。报告不能写到缓存或配置路径。

浏览器导航及渲染缓存保留hash路由。动态浏览器证据与API证据分别标识，不填写虚假的成功API来源。
缓存读取时也检查非空来源证据；`fetch_url`、`entry_mode` 加入身份。保留schema 2，不自动补写旧入口证据。
动态聚合读取后续页，重复整页和页数上限返回未完成；reference不会改写成forum，未验证的discovery路由拒绝猜测。
真实接口是否遵守所请求的分页参数仍须对实际站点验证，不能只用单元测试作来源验收。

HTTP重定向在发出下一跳前检查同源；保留最终URL；相对资源相对于所属文档解析；跨源附属资源不静默放行。
共享请求等待、域名请求槽和输出锁都有等待上限。
Playwright在可终止的专属进程内运行，超时后清理该进程树；只操作程序自己创建的进程，不终止用户的浏览器。
浏览器并发槽从4降至2，继续复用浏览器，不新建复杂调度框架。
BAT只调用固定Python启动器，用户输入不经过cmd命令拼接。

## 验证边界

提供离线反例和Windows CI，以及只访问内联data文档的Chromium冒烟测试。
没有运行生产全站抓取，没有改动 `sites.json` 或 `recent_10_cache.json`。
没有重建缓存、伪造历史来源、升级schema 3，或让缓存参与实时成功裁决。
旧缓存缺失入口身份时会明确拒绝混合历史，必须由实际来源审计后单独处理。
断电时多个独立文件仍不具有数据库式事务能力；现有写入保留异常回滚和单文件原子替换。
HTTP正文极慢传输等外部异常的完整墙钟截止仍需实际网络验收；不要把线程等待上限等同于所有底层I/O可强制终止。
