# 同期候选冲突闸：改造依据与实测记录

日期：2026-11-06　范围：`bantou/application/site_crawl.py`（唯一改动的业务文件）

## 一、问题

`crawl_site` 原本先把候选压成「只含边界那一个位置」的 `boundary_candidates`，再交给
`ambiguous_column_issues` 和 `same_period_position_conflicts`。后两者的判据都是「同一期出现在
不同位置」，入参已被压到单位置，因此生产链路上恒为空；页脚/页首另一条「半头」记录只要
落在边界位，就会被当作正文采纳，且不产生任何报错。

单元测试没暴露它，是因为测试直接调用这两个函数、喂未过滤的候选。

## 二、改造后的口径

1. 判定范围：**权威文档内同一期的全部候选**（不限边界位置）。
2. 去掉 `has_generic_half_head_anchor` 前置条件，18 个专属锚点站一并纳入。
3. **按开奖状态分组否决**：只比较与边界候选同一开奖状态（未开奖 / 已开奖）的同期候选。
   站点普遍把「当期未开奖记录（开？？/开0000）」与「已开奖的历史存档（开虎16）」并列写在
   同一页，两者不是同一类候选，跨状态比较会误杀当期值。
4. `ambiguous_column_issues` 仍只作用于边界位，避免把正常的历史表当成栏目歧义。
5. 该闸只做否决、不参与选取：边界仍由未过滤候选决定，非边界同期候选不决定选哪个值，
   只让归属不明的本站本期失败。

繁体「開」与简体「开」等价识别（烟花易冷站点使用繁体）。

## 七、残留

1. 记录里完全没有「开」字时，`draw_state` 默认按「已开奖」处理（保守方向：失败而非错值）。
   若某站当期记录不写开奖信息、同页又挂历史存档，会产生新的误杀，后续可加「未知」态。
2. 同一开奖状态、同一期、不同值的候选仍然判失败——这是刻意的 fail-closed，不做降级。

## 九、专属正则「异名栏目」通道排查（2026-11-06，真实页面 41/41）

排查动机：中途曾怀疑「异名栏目的广告可以按 `declared_special` 通过」。用真实页面逐站复核，
结论是该怀疑不成立，先前观察是合成样例的产物：

- 单独一行 `310期秒杀半头[4头单]开00准` 交给 `find_matches` 时，命中来源是 `structural`
  而不是 `declared_special`；而配了专属正则的站点在 `apply_secondary_site_scope` 里只保留
  `rule_id == "declared_special"`，`structural` 命中会被丢弃。
- 先前那次「被判成专属正则命中」是因为我把三行拼成一篇文档，记录切分把邻行并进了同一段，
  不是站点页面上的真实行为。

实测口径：41 个在 `sites.json` 里且配置了 `SITE_SPECIAL_VALUE_PATTERNS` 的站点，各抓当期
真实页面一次，统计同一期 `declared_special` 候选的栏目标签。

| 指标 | 结果 |
| --- | --- |
| 已核对站点 | 41 / 41（第一轮 6 线程 27 站，第二轮 2 线程补齐 14 站） |
| 同一期出现两种栏目标签的站点 | 0 |
| 单条记录里同时出现两种半头标签 | 0 |
| 同一期有多条 `declared_special` 候选的站点 | 7 |
| 其中两条值相同 | 3（贵人相助、脾气鬼怪、餐云卧石） |
| 其中值不同但开奖状态不同（当期 vs 存档） | 4（孙娘杀半头、气义相投、诸葛亮、正法眼藏） |
| 其中值不同且开奖状态相同（冲突闸会否决） | 0 |

静态补充：配置里只有两条正则用并列栏目名（995546.com→荆棘丛生、a.909922.com→手舞足蹈，
均为 `稳杀半头|绝杀半头`），两站真实页面各只出现一个标签（稳杀 / 绝杀），没有同时出现。

残留（非本次修复范围）：

- 约 12 条正则允许栏目标签与方括号值之间有 20~40 个字符（`[\s\S]{0,20,40}`）。当前页面的
  `declared_special` 片段里没有出现第二个半头标签，但这是「值可能取自邻近栏目」的窄通道，
  布局改动时需要复看。
- 本次是单期单页抽样，不是长期承诺；若广告位复读同一栏目名，标签判据失效，只能靠
  开奖状态分组的同期冲突闸兜。

## 十、单条候选闸（同日夜间追加）

动机：泛化锚点站如果本期在权威文档里只剩一条候选，就没有第二条同页记录可以对照，
正文没解析到、只剩页脚广告或存档时，程序会把它直接当正文采纳且不报错。

规则（只对 `anchors == ["半头"]` 且 `strict_half_head` 的站点生效，且仅当权威文档内
本期候选数为 1；证据全部来自页面，不读缓存）：

1. 候选有栏目标签，且该标签在同一权威文档的**另一期**记录里也出现过 → 通过。
2. 候选有栏目标签，但同文档其他期从未出现该标签 → 失败（典型：只剩页脚广告）。
3. 候选连栏目标签都提不出（裸「半头」）→ 失败，`单条候选且栏目名不可辨识`。
4. 同文档没有任何其他期记录可对照 → 失败，`单条候选且同文档没有其他期记录可对照`，
   并在收尾单独统计：`单条候选闸：栏目不可辨识 X 站，无其他期对照 Y 站`。

实现：`bantou/application/site_crawl.py`（`single_candidate_verdict` 与边界后判定），
失败分类 `单条候选无对照`（`bantou/outputs/formatting.py`）。

实测（2026-11-06 夜间，`--diagnose`，不写 TXT/缓存）：

| 期 | 改前成功 | 改后成功 | 规则可归因失败 | 说明 |
| --- | --- | --- | --- | --- |
| 310 | 74（00:00） | 67（00:45） | 2 站新增 | 8 站期间滚到 311、3 站 TLS 恢复，均与规则无关 |
| 311 | 24（00:05） | 31（00:40） | 2 站新增 | 11 站恢复是 311 陆续发布所致 |

规则实际命中的站点（三站合计，跨两期去重）：

| 站点 | 命中条款 | 现象 |
| --- | --- | --- |
| 简单拖鞋 | 第 4 条 | 文档只有本期一条半头记录，无对照 |
| 风生水起 | 第 4 条 | 同上 |
| 开几副辅 | 第 3 条 | 记录提不出栏目标签（裸半头） |

影响面 3/97（3.1%），按既定口径保持 fail-closed，未放宽。后续若要救回这三站，正确做法是
给它们收紧/指定专属锚点并逐站实抓验证，而不是放松本闸。

### 十之二、两条解析缺口的修复与代价边界（2026-11-06 夜）

**修复 1：对照池前移。** 单条候选闸的“其他期对照”取 `document_matches`（次级过滤之前的
同权威文档候选），不再取过滤后的 `identity_candidates`。

> 代价边界（必须记住）：对照池放到次级过滤之前，意味着被占位符/系列规则筛掉的其他期记录
> 也能作证。如果哪天正文完全没解析到、整页只剩一个每期都挂的页脚广告，这条闸会因为这个
> 标签“在别的期出现过”而放行。**本闸从此只负责拦“认不出栏目”“栏目孤例”，不再负责拦
> “整页只剩广告”**；后者仍由锚点、专属正则和同期冲突闸负责，不能把这里当兜底。

**修复 2：装饰符并入同一字符集。** `HALF_HEAD_LABEL_DECORATION` 常量同时供
`RAW_HALF_HEAD_LABEL_RE`（解析器取值）与 `column_labels`（栏目标签）使用，不再两套。
`正` 并入栏目标签噪声字，避免 `秒杀正半头` 被读成“秒杀正”。

真实数据回归（970 条缓存片段，新旧标签提取对比）：只有 10 条变化，全部是开几副辅由
`[]` 变成 `['绝杀']`（`301期 [绝杀㊣半头]1头双开:0000准` 一类），没有任何片段新增第二个
标签或丢标签 → 不新增栏目歧义误杀。

**修复后定向复测（只抓 3 站 × 310/311，未跑全站）：**
